# اعلان‌ها و هشدارهای عملیاتی

## کانال‌ها

| کانال | نقش |
|---|---|
| Inbox درون‌برنامه | مرجع اصلی و همیشه فعال |
| Push PWA | کانال بیرونی پیش‌فرض، با توجه به محدودیت‌های مرورگر/سیستم‌عامل |
| ربات تلگرام | اختیاری و با اتصال حساب |
| پیامک | فقط رویدادهای حیاتی و OTP |

## رویدادهای مهم

| رویداد | گیرنده |
|---|---|
| تسک جدید | کارآموز یا سرپرست گیرنده |
| تسک فوری یا مهلت امروز | کارآموز |
| تحویل جدید | سرپرست |
| بازگشت برای اصلاح | کارآموز |
| رد نهایی | کارآموز و ادمین |
| درخواست تعویق | سرپرست |
| بی‌پاسخی طولانی | ادمین دانشکده |
| تغییر سرپرست | سرپرست قبلی، سرپرست جدید و ادمین |
| OTP | کاربر درخواست‌دهنده |

## ضدآزار

- اعلان‌های هم‌نوع گروه‌بندی شوند.
- ساعات سکوت پیشنهادی ۲۱ تا ۷، به‌جز موارد حیاتی.
- برای رویداد غیرحیاتی از ارسال هم‌زمان چند کانال خودداری شود.
- Inbox مرجع باقی بماند؛ Push و Telegram قابل خاموش‌کردن باشند.
- SMS محدود و هزینه‌محور باشد.

## هشدارهای قاعده‌محور

- تحویل بررسی‌نشده بیش از SLA.
- کارآموز بدون نشست یا تحویل در سه روز کاری.
- تسک عقب‌افتاده.
- ظرفیت کاری بالاتر از آستانه.
- عقب‌ماندگی از ساعت هدف.
- رد نهایی نیازمند تصمیم ادمین.
- تسک توزیع‌نشده تا مهلت.
- قالب با نرخ بالای بازگشت یا رد.

هر هشدار باید قاعده، گیرنده و اقدام بعدی روشن داشته باشد؛ هشدار یا پیش‌بینی مبهم تولید نشود.
