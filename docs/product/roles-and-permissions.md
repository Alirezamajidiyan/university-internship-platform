# نقش‌ها، Scope و مجوزها

## مدل نقش

سه نقش محصول وجود دارد: `intern`، `supervisor` و `admin`. «ادمین دانشکده» و «ادمین سراسری» دو Scope برای نقش Admin هستند، نه نقش‌های مستقل. Leader حذف شده است.

یک حساب می‌تواند هم‌زمان بیش از یک نقش داشته باشد؛ برای مثال Supervisor و Faculty Admin. مجوز نهایی از ترکیب Role، Scope و رابطه داده به دست می‌آید.

## Scopeها

- `self`: فقط داده‌های خود کاربر.
- `supervised`: کارآموزان دارای رابطه فعال با سرپرست یا جانشینی فعال.
- `faculty`: فقط دانشکده‌های تخصیص‌یافته به ادمین.
- `global`: کل دانشگاه؛ مخصوص Admin سراسری.

## قواعد اجباری Backend

1. هر API باید مجوز را در سرور بررسی کند؛ مخفی کردن کنترل در PWA کافی نیست.
2. سرپرست فقط رابطه‌های فعال یا جانشینی فعال را می‌تواند مدیریت کند.
3. تاریخچه رابطه‌های قبلی پاک نمی‌شود.
4. سرپرست نمی‌تواند Assignment شخصی خودش را تأیید کند؛ بررسی‌کننده آن ادمین دانشکده است.
5. ادمین دانشکده به داده خارج از Scope دسترسی ندارد.
6. هر مداخله ادمین بر تسک نهایی، تغییر ساعت تأییدشده یا تغییر سرپرست باید دلیل و Audit Log داشته باشد.
