# چرخه عمر تسک و Assignment

## مدل سه‌لایه

| لایه | مفهوم | مثال |
|---|---|---|
| Task Template | تعریف نسخه‌دار قابل استفاده مجدد | بازرسی هفتگی تجهیزات |
| Task | نمونه اجرایی | بازرسی آزمایشگاه در هفته چهارم |
| Assignment | واگذاری به یک فرد | همان بازرسی برای یک کارآموز مشخص |

تسک گروهی یک Task با چند Assignment مستقل است. وضعیت، گزارش، شواهد و تأیید هر فرد جدا نگهداری می‌شود.

## وضعیت‌های Assignment

| وضعیت | شرح |
|---|---|
| `assigned` | تخصیص داده شده، شروع نشده |
| `in_progress` | کارآموز شروع کرده است |
| `blocked` | با مانع ثبت‌شده متوقف است |
| `submitted` | تحویل کارآموز؛ منتظر بررسی سرپرست |
| `changes_requested` | نیازمند اصلاح و تحویل مجدد |
| `approved` | تأیید نهایی |
| `rejected` | رد نهایی |
| `cancelled` | لغو شده پیش از تکمیل |

`overdue` وضعیت مستقل نیست؛ پرچم محاسبه‌شده بر اساس مهلت و وضعیت است.

## انتقال وضعیت‌ها

| از | به | عامل | شرط |
|---|---|---|---|
| — | `assigned` | Admin یا Supervisor | Scope معتبر و نوع تخصیص مجاز |
| `assigned` | `in_progress` | Intern | شروع فعالیت |
| `in_progress` | `blocked` | Intern | ثبت علت مانع |
| `blocked` | `in_progress` | Intern یا Supervisor | رفع مانع |
| `in_progress` | `submitted` | Intern | کامل بودن Definition of Done |
| `submitted` | `approved` | Supervisor | بررسی و تأیید |
| `submitted` | `changes_requested` | Supervisor | مشخص‌کردن بخش مشکل‌دار و بازخورد |
| `changes_requested` | `submitted` | Intern | تحویل مجدد |
| `submitted` | `rejected` | Supervisor | دلیل اجباری |
| وضعیت غیرنهایی | `cancelled` | سازنده مجاز یا Admin | دلیل |
| `approved` یا `rejected` | بازگشایی | فقط Admin | دلیل اجباری و Audit |

برای `supervisor_own` تأییدکننده ادمین دانشکده است، نه خود سرپرست. در `distribution` ادمین مأموریت توزیع را می‌سپارد؛ پس از توزیع، Assignmentهای مستقل کارآموزان به آن متصل می‌شوند.

## Definition of Done

هر قالب می‌تواند ترکیبی از این شواهد را الزام کند:

- تکمیل ریزتسک‌های الزامی
- متن گزارش با حداقل طول تعریف‌شده
- حداقل تعداد عکس
- فایل ضمیمه

دکمه Submit تا تکمیل شواهد الزامی غیرفعال می‌ماند و مورد ناقص را دقیق اعلام می‌کند.

## نسخه‌بندی قالب

ویرایش Task Template نسخه جدید تولید می‌کند. Taskهای موجود از نسخه اولیه خود مستقل می‌مانند. اعمال تغییر روی Taskهای باز باید یک اقدام صریح و پیش‌فرض آن غیرفعال باشد.

## تعویق

کارآموز درخواست تعویق با دلیل ثبت می‌کند؛ تا تصمیم سرپرست، Assignment تغییر نمی‌کند. در صورت تأیید، مهلت به روز کاری بعد منتقل می‌شود. محدودیت‌های تعداد و دفعات باید توسط Admin قابل تنظیم باشند و مقادیر اولیه سند (یک بار برای هر Assignment و سقف هفتگی پیشنهادی) فرضیه‌اند.

## رد نهایی

رد نهایی با بازگشت برای اصلاح متفاوت است. Assignment ردشده بسته می‌شود و در داشبورد Admin برای تصمیم بعدی می‌آید: تخصیص مجدد، بستن بدون اقدام یا بازگشایی.

## رویدادنگاری

هر تغییر وضعیت در `status_events` با عامل، زمان، وضعیت قبلی/جدید و دلیل ثبت می‌شود.
