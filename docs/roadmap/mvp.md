# محدوده MVP و نقشه راه

## P0 — هسته قابل استفاده

- کاربران، سه نقش و Admin Scope.
- دوره کارآموزی و ساعت هدف.
- رابطه تاریخ‌دار Intern و Supervisor.
- مکان درختی و نوع مکان.
- قالب رسمی تسک و نسخه‌بندی.
- Task، Assignment و سه نوع Assignment.
- Quick Task سرپرست.
- اجرا، Evidence Checklist، Submit، تأیید/بازگشت/رد.
- Work Session ورود/خروج.
- تأیید هفتگی ساعت.
- Inbox اعلان‌ها.
- Audit Log عملیات حساس.
- PWA موبایل‌محور کارآموز و پنل واکنش‌گرای مدیریت.

## P1 — تکمیل عملیات

- ورود گروهی کاربران و مکان‌ها از اکسل.
- درخواست تعویق و صف بررسی.
- گزارش انتقال هنگام تغییر سرپرست یا خروج کارآموز.
- هشدارهای SLA و نشست غیرعادی.
- خروجی گزارش ساعت و فعالیت.
- Push PWA.

## P2 — بهینه‌سازی

- اتصال اختیاری Telegram.
- بهبود جریان Offline برای عملیات امن و قابل همگام‌سازی.
- QR اختیاری برای تأیید حضور در صورت نیاز دانشگاه.
- تبدیل Quick Taskهای پرتکرار به قالب رسمی.
- گزارش‌های مقایسه‌ای و فیلترهای پیشرفته.

## خارج از محدوده MVP

- نقش Leader مستقل.
- ارزیابی مهارت و Skill Passport.
- GPS دائمی.
- نقشه گرافیکی دانشگاه.
- Microservices و مقیاس‌پذیری سنگین.
- تخصیص خودکار هوشمند و تصمیم‌گیری AI.
- HR، حقوق و دستمزد یا حضور و غیاب پیچیده.

## ترتیب پیشنهادی اجرا

1. مدل هویت، نقش، Scope و روابط.
2. دوره‌ها و مکان‌ها.
3. قالب تسک، Task و Assignment.
4. اجرای تسک، تحویل و بررسی.
5. ثبت ساعت و تأیید هفتگی.
6. داشبوردها، اعلان‌ها و Audit.
7. ورود/خروج گروهی و عملیات گزارش‌گیری.

## معیار آماده بودن MVP

- یک Admin بتواند دانشکده، دوره، کاربران، سرپرست‌ها و قالب تسک را مدیریت کند.
- Supervisor بتواند Quick Task بسازد و فعالیت را به کارآموزان خودش تخصیص دهد.
- Intern بتواند تسک را ببیند، انجام دهد، شواهد ثبت کند و تحویل دهد.
- Supervisor بتواند تحویل را تأیید، اصلاح‌خواهی یا رد نهایی کند.
- Intern بتواند ساعت را با ورود/خروج ثبت کند و Supervisor ساعت هفتگی را تأیید کند.
- هیچ کاربری خارج از Scope خودش نتواند داده را از API دریافت یا تغییر دهد.
- عملیات حساس قابل ممیزی باشد.
